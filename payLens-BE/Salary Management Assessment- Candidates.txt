Assessment with Product Framing

 
Expectations 
This exercise is intentionally designed to assess how you think, design, and build software in an AI-driven environment.  
You are required to use AI tools to accelerate your work. We care about how you use them, the clarity of your thinking, and the quality of your engineering decisions.  
   
We expect you to:  
- Demonstrate clarity in thought and structured problem solving  
- Show strong engineering fundamentals & product thinking 
- Make thoughtful architectural and design decisions  
- Write production-quality code and tests  
- Use AI intentionally while maintaining correctness and quality  
Please make incremental commits so we can understand how your solution evolved. 

Goal: 
Build employee salary management software for an organization with 10,000 employees. 

User Persona: 
HR Manager of the org 

Problem Statement: 
Currently, ACME org's HR team manages salary data for 10,000 employees across multiple countries, with everything managed via excels, which is tedious. We want the HR manager to manage the salaries data via web-based software and be able to answer questions about how the org pays people. 

Requirements: 
Write a one-page requirements document before building the software, outlining the goal, scope & features, and what you are deliberately leaving out, and reasoning for it.

Technical Constraints: 
You should build end-to-end, fully functional software, including backend & UI. 
1. Backend: 
- {Language & Framework as per JD (preferred) or any other framework of your choice. Relational database of your choice, like SQLite.

2. UI: 
- ReactJS or NextJS. AngularJS with Java
- Component library of your choice 

3. Seeding: 
- Seed script with 10,000 employees. 

4. Readiness: 
- Fully functional deployed software 
- Any video demo of the software 

Development Approach: 
Using agentic AI tools of your choice, build the solution while maintaining high standards of code quality and test coverage. 
Your solution should include: 
- A meaningful set of unit tests that cover the core functionality 
- Tests that are fast, deterministic, and easy to understand 
- Good code structure, readability, and maintainability 
Your commit history should show the evolution of your solution through incremental commits. This helps us understand how you approached the problem and how your implementation developed over time.

1. Salary Definition & Scope: Focus strictly on base salary (along with native currency). Bonuses, equity, allowances, or CTC breakdowns are out of scope for this MVP.

2. Effective-Dated Salary Changes: Managing the current salary per employee is completely sufficient. Detailed revision logs and effective-dated history can be safely deferred as future phase enhancements.

3. Multi-Country Comparison: Store each employee's salary in their native local currency for individual records, and normalize org-wide totals to a common base reporting currency (e.g., USD) via a simple, static/seeded exchange-rate table. Deterministic seeded data is preferred; live FX API integration is not expected.

4. Answering Pay Questions: Focus on structured visual dashboards, KPI cards (total payroll spend, headcount, average/median salary), and interactive filters (by country, department, role). Natural-language or AI-assisted querying is strictly an optional stretch feature.

5. AI Expectations: The primary evaluation focus is on how you leverage AI during the development process (and documenting your AI workflows and prompts in your write-up). Building AI features directly into the product itself is strictly optional.

6. Access Control & Privacy: You can explicitly scope authentication and RBAC out. Assume an already-authorized, single HR Manager persona with full visibility-simply note auth, SSO, and RBAC as future production considerations in your requirements document.

7. Data Volume & Performance: Treat the 10,000 synthetic employee records as your primary functional dataset. Demonstrate performance through efficient server-side pagination, indexing, filtering, and database/JPA analytical queries.

8. Assessment Priorities: We prioritize clean layered architecture (Controller → Service → Repository → Domain), robust unit testing (JUnit 5 and Mockito), server-side performance at scale, thoughtful domain modeling, and clear documentation (including your trade-offs and AI workflow summary).

Please capture these scope decisions, data model assumptions, and intentional trade-offs in your one-page requirements document before diving into implementation.
